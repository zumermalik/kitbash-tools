# Kitbash SEO And Content Strategy

## SEO Thesis

Each Kitbash tool is a search landing page with a real working utility at the top. The product should grow through many focused, high-intent pages rather than one broad homepage.

## URL Structure

Use clean tool routes:

```txt
/
/tools
/tools/typewriter-invoice
/tools/color-palette-generator
/tools/wcag-contrast-checker
/tools/image-compressor
/tools/qr-code-generator
/tools/favicon-generator
```

## Page Structure

Each tool page should follow this order:

1. Tool interface.
2. Short benefits section.
3. How it works.
4. Use cases.
5. Related tools.
6. FAQ.

The working tool must come before long SEO copy.

## Metadata Model

Each tool should define:

- title
- meta description
- canonical URL
- Open Graph title
- Open Graph description
- Open Graph image
- related keywords
- FAQ entries
- structured data type

## Internal Linking

Every tool page should link to:

- the main tool directory
- two related tools
- the flagship invoice tool where relevant

Examples:

- Image compressor links to image converter and favicon generator.
- Palette generator links to contrast checker and gradient generator.
- Invoice generator links to quote calculator and PDF export-related content.

## Content Tone

Kitbash copy should be concise, useful, and visually literate. Avoid hype. The tone should feel like a tasteful studio tool, not a generic conversion website.

## Programmatic Expansion

Later, generate comparison and task-specific pages:

- PNG to WebP converter
- JPG to WebP converter
- compress PNG online
- orange color palette generator
- invoice template for freelancers
- invoice template for designers

These should only be added once the base tools are strong and avoid thin-content pages.

## Structured Data

Use structured data where appropriate:

- `SoftwareApplication`
- `WebApplication`
- `FAQPage`
- `BreadcrumbList`

## Content Quality Rules

- The tool itself is the primary value.
- Do not publish pages where the tool does not satisfy the query.
- Keep content accurate and specific.
- Add screenshots or generated examples when useful.
- Avoid duplicate boilerplate across tool pages.
